Remaining preview findings

High · Unknown paths still return 200 on the preview host

Evidence: evidence/http-evidence.json: missing status 200; missing.html has homepage title/index,follow; browser-evidence.json later shows a noindex 404 UI.

Proposed action: Verify static 404 generation and final hosting configuration together after deployment. Do not mark server response behavior fixed solely because /404.html exists.

Low · Rendered error social descriptions retain homepage copy

Evidence: missing-rendered og:title/twitter:title correctly become Page Not Found, but og:description and twitter:description still describe the portfolio. The direct static 404 document has correct error descriptions.

Proposed action: Make the dynamic error head use the localized error descriptions too, then check direct navigation and client navigation.

Low · Social description punctuation is garbled

Evidence: Browser OG/Twitter description contains Unicode U+00E2 U+20AC U+201D where an em dash is intended. The same mojibake occurs in baseline evidence, so this is newly noticed, not a proven new regression.

Proposed action: Correct the source description string with proper UTF-8 punctuation and regenerate; raw response is valid UTF-8, so changing HTTP charset alone will not repair it.

Scope and limitations

  • Preview only: rusiru.cc and its www variants were not refetched. No fixes are claimed live in production.
  • The intended production canonical, sitemap locations and share-image URLs remain on rusiru.cc. Cross-host canonical references are expected here, not automatic defects.
  • The 200-page advanced cap discovered one same-host HTML page. Nine supplemental HTTP endpoints, three browser states and one preview image were checked.
  • Preview robots.txt permits crawling and its homepage is index,follow. A production canonical is a hint, not a preview access control. Decide preview indexation policy separately; do not accidentally add production noindex.
  • Local source is behind deployed preview commit 720795a3764bb2012d5d1dab5f5a0540685b14aa. New fix verification relies on preview HTTP/browser evidence, not stale source line assumptions.
  • No GSC, Bing, GA4, search-performance, backlink, keyword, competitor or AI-visibility evidence was supplied. Those account-dependent checks remain untested.
  • Lab LCP/CLS are single unthrottled cache-disabled observations. No Lighthouse score, INP measurement or real-user CWV pass/fail is reported. Cross-host before/after timing is not a controlled experiment.
  • The packaged auditor still emits all 54 statuses as Not tested because it compares string CSV IDs with integers; raw files are preserved. The reviewed checklist is the authoritative human-reviewed result for this recheck.
  • No source edits, automatic fixes, commits, deployment or account changes were made. proposed_fixes.patch is empty; no rollback is needed.
