Prioritized findings and proposed remediation

SEO-01 · High · Missing pages return HTTP 200 and homepage HTML

Evidence: evidence/http-evidence.json (missing/home hashes); evidence/missing-rendered.jpg; netlify.toml:5-8; src/pages/NotFound.tsx:20-33

Implication: Wrong success responses create a soft-404 risk. A genuine Google soft-404 classification is not confirmed without Search Console.

Proposed action: Generate a localized static 404.html through the existing generator and remove or narrow the blanket 200 SPA rewrite. There is only one intended public document; fragments do not require a catch-all rewrite. Use Netlify custom-404 handling or an explicitly verified 404 rule.

Verification after a future fix: After a preview deployment, / must return 200; a random path must return 404 before JavaScript and show an appropriate error document; /#projects, real assets, robots and sitemap must still work.

Primary technical reference

SEO-02 · Medium · Server metadata and React Helmet create duplicate/conflicting head tags

Evidence: evidence/browser-evidence.json: homepage has two descriptions and two canonicals; missing-rendered has homepage/error canonicals and index/noindex. scripts/search-content.ts:39-50; src/pages/Index.tsx:32-38; src/pages/NotFound.tsx:20-33

Implication: Duplicates on the homepage currently agree; on the error route they disagree. This complicates canonicalization and metadata maintenance; no ranking penalty is claimed.

Proposed action: Use one metadata owner per rendered field. For Helmet-managed tags, serialize the expected ownership markers in static output or avoid re-inserting identical homepage tags. Ensure error responses have route-appropriate metadata from the server.

Verification after a future fix: Count tags before and after rendering: one canonical, one description, and one appropriate robots directive on each tested route.

SEO-03 · Medium · Education logos are much larger than their displayed size

Evidence: evidence/browser-evidence.json: ucsc 500x500/92,158 bytes, mcg 337x337/79,370 bytes; both render at 44x44. src/components/sections/Education.tsx:30

Implication: About 167.5 KiB of source PNG logo data for two small graphics, although lazy loading defers their initial mobile requests.

Proposed action: Create optimized high-density logo variants and reference them through siteConfig.educationLogos. Add a repeatable asset optimization command; preserve transparency and visual quality.

Verification after a future fix: Inspect final dimensions/bytes, verify logos at 1x/2x/3x display density and confirm no layout shift or broken paths.

Verification after a future fix: Compare repeated controlled runs and inspect field p75 LCP/INP/CLS when data exists. Do not compare these cold desktop and warm mobile samples as device scores.

Evidence: evidence/http-evidence.json: http://www.rusiru.cc/ -> https://www.rusiru.cc/ -> https://rusiru.cc/ (301 + 301). Other tested variants take one hop.

Implication: A small extra request for that variant; canonical consolidation already works.

Primary technical reference

What is already working

  • Homepage responds over verified HTTPS with readable, substantial server-side HTML fallback.
  • robots.txt references the live, valid, canonical sitemap; both return HTTP 200.
  • Tested HTTP/www variants converge on the HTTPS apex with permanent redirects.
  • One H1 is present in raw and rendered homepage states; primary fragment navigation resolves.
  • Observed images have alt text, local resources load successfully, and 390px mobile rendering has no horizontal overflow.
  • JSON-LD is parseable and llms.txt is available; neither establishes rankings or AI citations.

Coverage, limitations and verification

  • One canonical portfolio HTML document was discovered using an advanced crawler cap of 200. A cap is not a statement that 200 pages exist or were audited.
  • Supplemental evidence covers ten requested URL/host variants and three browser states: desktop, mobile and one intentional missing URL.
  • No GSC, Bing, GA4, rankings, backlink, competitor, outreach or AI-visibility account evidence was supplied. Actual index status, selected canonical, clicks, CTR and manual actions remain unknown.
  • The blog subdomain and outbound destinations were not crawled. The main-host sitemap is correctly limited to its one canonical page; fragments and external blog URLs were not added.
  • Desktop and mobile browser samples were unthrottled and shared a browser cache. The first desktop sample was cold; mobile was warm. No Lighthouse score, INP measurement or field-CWV pass/fail is reported.
  • Mobile screenshots show no overflow at 390px; a complete accessibility/device matrix was not performed. Lazy mobile logos were not yet requested at the initial viewport, not broken.
  • The packaged source scanner reported four heuristic warnings: three in unprocessed index.html and one in the design prototype. Live generated metadata/H1 are present, so those warnings are not promoted to production failures.
  • The raw packaged checklist labeled all 54 tasks Not tested because its comparisons use integer item numbers while CSV IDs are strings. Raw outputs are retained; this reviewed report and reviewed-audit.csv incorporate independently verified evidence instead.
  • Codebase proposed_fixes.patch is empty; no safe same-host HTTP upgrades were identified. Application source, configuration and deployment were not changed by this audit.

Rollback: No source changes or deployment were made. No application rollback is needed.
